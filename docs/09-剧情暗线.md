# 09 · 剧情暗线（第一版草稿）

## 已确认的底层设定

- 空间是现实的映射，近似意识宫殿。玩家是主角的意识，奶龙是潜意识。
- 噜噜对应童年切片；牛来对应青春期依赖母亲又渴望独立的矛盾；袋鼠对应独自讨生活、因未能混出样子而不敢回去的矛盾。
- 奶包是外部环境影响的象征，不是知道全部真相的解说员。贝利亚仅是未来设想，本轮不加入。
- 接纳意味着承认过去的切片属于自己、重新整合，而非消灭角色。空间最后仍存在；危险可以结束，但不等于现实困难或疾病自动消失。

## 本轮落地的入口

文字是可修改的叙事草稿，不把生活细节写成不可更改的完整传记。

1. **选夜界面**：五个夜晚按钮下放简短生活残片。只显示已解锁夜晚的文字；未解锁显示省略号。不另加弹窗，原按钮仍直接开局。
2. **成就界面**：原名称和明确的达成条件保留。点已解锁的条目，底部显示 `Flavor`；未解锁不给故事旁白。前三个故事成就与厨房、临近天亮的成就形成书包、饭盒、报平安等交叉线索。已有解锁也能回看。
3. **主动电话**：每夜首通旧台词之后追加一句奶包闲话，最多四句。她转述、赞许或质疑外界评价，不直接解释角色身份。旧字幕与音频不改；新句 `Id` 为空，先仅字幕，不调用 TTS。永夜、自定义夜与重复电话不加这句。

生活线：等人来接 → 说不用接却回头看 → 嫌叮嘱却带走饭盒 → 报平安时删掉难处 → 搬家仍带着旧物。

## 明确没有做的事

- 多结局开放条件尚未确定，**不实现结局系统、好坏结局、阅读计数、收集进度或接纳值**。
- 不统计关门多少来评价人格，不要求玩家放弃防御、故意被抓或冒险读字。
- 不新增强制过场、场景调查、可移动角色或战斗机制。
- 不改五夜解锁与现有结算，不将正常五夜通关宣称为已经完成融合。

## 工程位置与验证

- `Assets/Scripts/Gameplay/StoryFragments.cs`：纯 C# 生活片段与无配音电话句。
- `Assets/Scripts/Gameplay/NaibaoPhoneScript.cs`：五参 `ForCall` 仅对显式故事标记追加，原重载保持原行为。
- `Assets/Scripts/Core/GameManager.cs`：排除永夜、自定义夜后才请求故事片段。
- `Assets/Scripts/UI/PrototypeScene.Menu.cs`：选夜片段刷新、成就可点击回看。
- `Assets/Tests/EditMode/StoryFragmentsTests.cs`：四例，覆盖五夜数据、旧配音不变、重复/自定义不追加、成就条件保留。

新电话句独立于旧通话 JSON 编辑器维护，目前改 `StoryFragments.cs`。以后若要录音，应先定稿、增加独立语音 ID，再补资源；不能借用旧 ID。
