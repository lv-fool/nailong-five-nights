# 10 · 安卓移植

> 2026-10-25 起做安卓版。分支 `android-port`。
> 结论先行：**核心逻辑零改动**（电量 / 时钟 / 敌人 AI 是纯 C#），改动全部集中在
> 输入层、跳杀视频加载和打包配置。

## 一、改了什么

### 1. 触屏输入（`PrototypeScene.cs`）

桌面行为**一字未动**（`Application.isMobilePlatform` 分流，编辑器里照旧用鼠标）：

| 操作 | 桌面 | 触屏 |
|---|---|---|
| 转头 | 鼠标**绝对位置**映射（`UpdateView`） | **拖动相对位移**（`UpdateViewTouch`）：横向拖多少转多少，松手停在原地；点按（位移 < 屏宽 0.8%）不动视角 |
| 升降监控 | 鼠标划进底部 10% 边缘 | **点按底部**（`HandleMonitorHotspotTouch`）：拖动扫过底部不算，防乱切 |
| 点手机接奶包 | 鼠标点到亮起的手机 | 同左（触摸镜像成鼠标），但**拖动收尾**落在手机上不算点 |
| 手电筒 / 门 / 灯 / 通话条 | UGUI 按钮 | 原样可用（指针事件天然支持触屏，无需改动） |
| 空格 / F 继续跳过通话 | 键盘 | 用通话条右侧的「继续 / 挂断」按钮（按钮本来就有，只是提示文案按平台分流了） |
| 返回键 | Esc（永夜模式开暂停） | 安卓返回键 = Escape，直接可用；`Input.backButtonLeavesApp = false` 在 `Awake` 显式声明（Unity 默认就是 false，按返回不会退应用） |

手感参数（真机不对只调这两个）：
- `TouchDragGain = 5f` —— 拖 20% 屏宽满转，和桌面鼠标行程一致
- `TouchTapSlopFrac = 0.008f` —— 点按/拖动的分界（2400 宽的屏约 19px）

### 2. 跳杀视频（`PrototypeScene.cs` `TryPlayJumpscareVideo`）

安卓的 StreamingAssets 在 APK 压缩包里：`File.Exists` 恒为 false、`Path.Combine` 拼
反斜杠 —— 原代码会让四条视频**静默退回静态图**。现按 `UNITY_ANDROID` 分流：
不做存在性检查，`streamingAssetsPath + "/" + 相对路径` 直接当 URL 喂 VideoPlayer；
起不来照样走 `errorReceived` 兜底。

### 3. 打包脚本（`Assets/Editor/BuildAndroid.cs`，菜单「奶龙 / 11. 打包安卓版」）

- 先探测 `PlaybackEngines/AndroidPlayer/Variations` 在不在，缺了给中文人话提示
  （= Android Build Support 模块没装全）
- IL2CPP + **ARM64**（minSdk 22）、包名 `com.lvfool.nailongfivenights`、版本 1.0.0/1
- **锁横屏**（左右各一，禁竖屏）
- 纹理压缩默认 ASTC，出 APK（`adb install` 侧载用；上架再改 AAB + 自有 keystore）
- **全景贴图安卓覆盖**：`office_pano.png` 的 8192 上限是按 Windows 设的，导入设置
  分平台 —— 脚本打包前自动给 Android 覆盖 8192 + ASTC_6x6（不覆盖真机上全景糊掉）

### 4. 调试入口（手机没有 F1）

桌面按 F1 开调试面板，手机没键盘 —— 2026-10-27 加了两级触屏入口：

- **解锁彩蛋**：标题页右下角版本号（`v1.0.0`）**2 秒内连点 5 次** → 变金色 `DEBUG`，
  解锁状态写进 `PlayerPrefs` 键 `nl_debug_unlocked`（存一次就一直有，重装 / 清 App 数据才重置）。
  没点满时标签会显示「再点 N 次」，普通玩家看不出来这是个入口。
- **局内开关**：解锁后局内右上角常驻 `DBG` 小按钮（进夜显示、回菜单隐藏，由 `SyncDebugToggle` 控制），
  点它开关调试面板 —— 和桌面 F1 共用同一个 `ToggleDebugPanel()`。
- **调试面板多一行「控制」**：`重开` / `上一夜` / `下一夜`，对应桌面的 R / [ / ] ——
  没键盘也能重开一局或跳夜验证（`BuildDebugControls`，`PrototypeScene.cs`）。

⚠️ 想给别人干净的截图/包，先确认标题页版本号不是金色的；解锁状态在 PlayerPrefs 里，不清数据不会消失。

## 二、怎么打包

### 2.1 环境前提（2026-10-25 实录，换机器照此重来）

这台机器的编辑器是**手动添加**进 Hub 的（`%APPDATA%\UnityHub\editors-v2.json` 里
`manual: true`），Hub 的「⋯ → 添加模块」对这种安装**不出现**。补装走官方独立安装包：

1. **播放器引擎**（Variations，455 MB）：从 Hub 缓存 `%APPDATA%\UnityHub\releases.json`
   里查到 changeset（2022.3.62f3c1 = `1623fc0bbb97`），下
   `https://download.unitychina.cn/download_unity/1623fc0bbb97/TargetSupportInstaller/UnitySetup-Android-Support-for-Editor-2022.3.62f3c1.exe`
   静默装：`安装包.exe /S /D=F:\Unity\2022.3.62f3c1`（`/D=` 必须最后、不带引号，指向版本根目录）。
   ⚠️ 这个安装器会**清空重建 `AndroidPlayer` 下的 SDK/NDK/OpenJDK 目录**——先装它，再补工具
2. **SDK / NDK / JDK**（国内直连：腾讯镜像 + Unity 中国 CDN；`dl.google.com` 需走本机代理）：

   | 组件 | 放哪 | 来源 |
   |---|---|---|
   | OpenJDK 11（120 MB） | `AndroidPlayer/OpenJDK/`（zip 根目录直解，`bin/java.exe` 直接在里面） | `download.unitychina.cn/download_unity/open-jdk/open-jdk-win-x64/jdk11.0.14.1-1_….zip`（全名见 Hub releases.json） |
   | NDK r23b（752 MB） | `AndroidPlayer/NDK/`（zip 顶层 `android-ndk-r23b/` 的**内容**上提） | `mirrors.cloud.tencent.com/AndroidSDK/android-ndk-r23b-windows.zip` |
   | platform-tools | `SDK/platform-tools/` | 腾讯镜像 `platform-tools_r32.0.0-windows.zip` |
   | build-tools 34 | `SDK/build-tools/34.0.0/`（zip 顶层叫 `android-14`，**要改名**） | 腾讯镜像 `build-tools_r34-windows.zip` |
   | platform-34 | `SDK/platforms/android-34/` | 腾讯镜像 `platform-34-ext7_r02.zip` |
   | cmdline-tools | `SDK/cmdline-tools/latest/`（zip 顶层 `cmdline-tools/` **要改名 latest**，Unity 硬性要求 `latest/bin/sdkmanager.bat` 存在） | 腾讯镜像 `commandlinetools-win-8092744_latest.zip` |
   | 许可文件 | `SDK/licenses/android-sdk-license`，内容写三行标准哈希（8933bad1…、d56f5187…、24333f8a…） | 手写 |

3. **注册表开关**：一旦有构建在「bundled JDK 缺失」时失败过，Unity 会把
   `HKCU\Software\Unity Technologies\Unity Editor 5.x` 里的
   `JdkUseEmbedded_h2297287597` 置 0 并**不再回头检查**——补完 JDK 后要手动改回 1，
   否则永远「JDK not found」。NDK/SDK 没有对应的坑（没有预置的失败标记）

### 2.2 出包

1. 菜单「奶龙 / 11. 打包安卓版」（或命令行 `-executeMethod NailongFNAF.EditorTools.BuildAndroid.Build`）
2. 产物 `Builds/Android/NailongFiveNights.apk`（2026-10-25 首包实测：**117 MB，IL2CPP + ARM64，错误 0 警告 0，140s**）

装到真机：

```
adb install -r Builds/Android/NailongFiveNights.apk
adb logcat -s Unity      # 看运行日志
```

adb 在 `F:\Unity\2022.3.62f3c1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\`，
或用 platform-tools 独立版。手机要开「开发者选项 → USB 调试」。

⚠️ **命令行出包**（`-batchmode -quit -projectPath "..." -executeMethod NailongFNAF.EditorTools.BuildAndroid.Build -logFile "..."`）
必须确认**没有别的 Unity 实例开着这个项目**，否则会崩在 `HandleProjectAlreadyOpenInAnotherInstance`
（2026-10-27 实录：跑完 `-runTests` 的无头测试进程没退、攥着 `Temp/UnityLockfile`，紧接着打包就崩了）。
先 `Get-Process Unity | Stop-Process -Force` 再出包。区别：`-runTests` 不能加 `-quit`（测试会被掐断），
打包加 `-quit` 是安全的。

⚠️ 打过安卓包后项目的**活动构建目标会留在 Android**，回桌面开发要
File → Build Settings 切回 Windows；切换会触发一轮重导入（几分钟）。

## 四、已知边界

- ⚠️ **现有 APK 还不含调试入口**：`Builds/Android/NailongFiveNights.apk` 是 2026-10-25 21:13 打的，
  2026-10-27 才加的调试入口（标题页版本号 2 秒连点 5 次解锁 `DBG`）不在包里，
  重打包后第三节最后一项才验证得了。重打包命令见 2.2，成功标志是日志里的 `BUILD-OK` 行
- **构建管线已验证**：APK 已在 2026-10-25 无头构建成功（117 MB，IL2CPP + ARM64，
  0 错误 0 警告）。**触屏手感还没上过真机**——第三节清单要装到手机逐项过，
  尤其 `TouchDragGain` 大概率要调
- 跳杀视频层是按 16:9 铺的，超宽屏上会裁边（跟桌面一致的设计，非 bug）
- 相机挖孔 / 异形屏的 safe area 没做，UI 极边缘元素可能被挡，遇到再说
- 上架 Google Play 才需要：自有 keystore、AAB、64 位（已是）—— 侧载分发不用管
