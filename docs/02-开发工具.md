# 02 · 开发工具：MCP for Unity

让 AI 助手直接操作 Unity 编辑器的桥接包。装上之后，AI 可以读 Console、创建对象、
改组件属性、跑测试、进 Play 截图 —— 不用人手动点菜单或截图。

- 包名：`com.coplaydev.unity-mcp` v10.3.0
- 项目地址：<https://github.com/CoplayDev/unity-mcp>（MIT 许可）
- 支持 Unity 2021.3 → 6.x

> Unity **官方**的 MCP 服务器只支持 Unity 6 且需要付费订阅，本项目用的是社区版。

---

## 一、装法：本地嵌入包

官方推荐的装法是 Unity 里走 git URL：

```
Window → Package Manager → + → Add package from git URL
https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main
```

如果这台机器 git 直连 GitHub 不通（国内网络常见，`schannel` 证书吊销检查失败），
就改用**本地嵌入包**：把包直接放进项目，Unity 当本地包加载，完全不联网。

### 本地嵌入的步骤

1. 下载仓库压缩包（浏览器直接开这个链接）：
   ```
   https://codeload.github.com/CoplayDev/unity-mcp/zip/refs/heads/main
   ```
2. 解压，把里面的 **`MCPForUnity`** 文件夹整个复制到 `<项目>/Packages/` 下
3. 确认 `Packages/manifest.json` 里有它需要的两个非内置依赖：
   ```json
   "com.unity.nuget.newtonsoft-json": "3.0.2",
   "com.unity.test-framework": "1.1.31"
   ```
4. 打开 Unity，等它解析完包

> `Packages/MCPForUnity/` 已在 `.gitignore` 里，**不进版本库** ——
> 所以克隆仓库的人都需要按上面这四步自己装一次。

## 二、客户端配置

MCP 客户端里加一条 stdio 类型的 server：

```json
"unityMCP": {
  "command": "uvx",
  "args": ["--from", "mcpforunityserver", "mcp-for-unity", "--transport", "stdio"],
  "env": {
    "UNITY_MCP_STATUS_DIR": "<你的状态目录>"
  }
}
```

`uvx` 需要能跑（`uv --version`）；它第一次会用 `mcpforunityserver` 这个 PyPI 包。
具体写在哪个文件、怎么让它生效，随客户端不同 —— 常见客户端是改完配置要**完全退出重开**。

### ⚠️ 那个 `env` 不能省

有些 MCP 客户端启动 server 时**不传 `USERPROFILE` / `HOME` 环境变量**，
于是 Python 的 `Path.home()` 抛 `RuntimeError: Could not determine home directory`，
server 就找不到 `~/.unity-mcp` 下的状态文件，报「No Unity Editor instances found」。

`UNITY_MCP_STATUS_DIR` 让 server 跳过 `Path.home()` 直接定位状态目录，绕开这个问题。

## 三、Unity 端的两个前提

1. **Transport 必须是 `stdio`**（`Window → MCP for Unity` 面板里改）
   - 选 HTTPLocal 时 Unity 不开 TCP bridge；如果本机 `8080` 端口被别的软件占着，
     HTTP 模式也走不通
   - **改完要重启 Unity** —— stdio bridge 的启动逻辑写在静态构造函数里，
     只在域加载时执行一次，不重启不生效
2. **Unity 要一直开着** —— bridge 跑在 Unity 进程里，监听 `127.0.0.1:6400`

> ⚠️ **编辑器开着的时候，别试图用命令行 `-batchmode` 构建同一个项目** ——
> `Temp/UnityLockfile` 被占着，会报「another Unity instance is running with this project open」。
> 直接走 MCP 的构建工具。

## 四、排障

| 症状 | 处理 |
|---|---|
| Unity Bridge 连不上 | `Window → MCP for Unity` 看状态面板，必要时重启 Unity |
| Server 起不来 | 终端确认 `uv --version` 能跑；确认 `UNITY_MCP_STATUS_DIR` 已设 |
| 客户端连不上 | 确认 server 在跑、JSON 配置合法、客户端已重启 |
| 日志 | 状态目录下的 `Logs/unity_mcp_server.log`。出现 `Discovered 0 Unity instances` + `No Unity Editor instances found on startup` = server 会立刻自杀，说明状态目录或 Unity 端 transport 不对 |

## 五、连上之后能做什么

项目里的用法见 `AGENTS.md` 第六节。常用工具：

| 工具 | 用途 |
|---|---|
| `run_tests` + `get_test_job` | 跑 EditMode 测试并取结果 |
| `read_console` | 读 Console 报错 / 警告 |
| `manage_editor` | 进 / 出 Play 模式 |
| `manage_camera` | 截图（**注意默认输出到 `Assets/Screenshots/`，会污染仓库**） |
| `manage_build` | 出构建 |
| `execute_code` | 在编辑器里跑一段 C#（反射操纵运行时状态很有用） |
