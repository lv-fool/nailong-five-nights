# 02 · 开发工具：MCP for Unity

让 AI 助手直接操作 Unity 编辑器的桥接包。装上之后，AI 可以读 Console、创建对象、
改组件属性、跑测试——不用你手动点菜单或截图。

- 包名：`com.coplaydev.unity-mcp` v10.3.0
- 项目地址：https://github.com/CoplayDev/unity-mcp （MIT 许可）
- 支持 Unity 2021.3 → 6.x

> Unity **官方**的 MCP 服务器只支持 Unity 6 且需要付费订阅，本项目用的是社区版。

---

## 本机为什么没用标准装法

官方推荐的装法是 Unity 里走 git URL。但**这台机器上 git 直连 GitHub 会失败**：

```
fatal: unable to access 'https://github.com/...':
schannel: next InitializeSecurityContext failed:
CRYPT_E_NO_REVOCATION_CHECK (0x80092012) - 吊销服务器无法检查证书是否吊销
```

证书吊销检查走不通（国内网络常见）。试过的绕法都无效：
`http.schannelCheckRevoke=false` 报同样的错，`http.sslBackend=openssl` 变成缺根证书。

但 **curl 是通的** —— WorkBuddy 自己设了代理环境变量（`http_proxy=127.0.0.1:xxxxx`），
curl 走它就能访问 GitHub，git 没走。

所以改成**本地嵌入包**：把包直接放进项目，Unity 当本地包加载，完全不联网。

## 当前安装状态

```
<项目>/Packages/MCPForUnity/     ← 包本体（4.9 MB，744 个文件，自带 .meta）
```

该目录已加入 `.gitignore`，**不进版本库**。

`Packages/manifest.json` 里额外声明了包的两个非内置依赖：

```json
"com.unity.nuget.newtonsoft-json": "3.0.2",
"com.unity.test-framework": "1.1.31"
```

## 换机器 / 重装时怎么恢复

1. 下载仓库压缩包（浏览器直接开这个链接）：
   ```
   https://codeload.github.com/CoplayDev/unity-mcp/zip/refs/heads/main
   ```
2. 解压，把里面的 **`MCPForUnity`** 文件夹整个复制到 `<项目>/Packages/` 下
3. 确认 `Packages/manifest.json` 里有上面那两个依赖
4. 打开 Unity，等它解析完包

> 如果哪天 git 能直连 GitHub 了，用官方 git URL 更省事：
> Window → Package Manager → `+` → Add package from git URL →
> `https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#main`

## MCP 客户端配置

写在 `C:\Users\DELL\.workbuddy-ai\mcp.json` 里：

```json
"unityMCP": {
  "command": "C:/Users/DELL/AppData/Local/hermes/bin/uvx.exe",
  "args": ["--from", "mcpforunityserver", "mcp-for-unity", "--transport", "stdio"],
  "env": {
    "UNITY_MCP_STATUS_DIR": "C:/Users/DELL/.unity-mcp"
  }
}
```

**改完 `mcp.json` 必须完全退出 WorkBuddy 再重开才生效。**
重开后到「连接器管理 → 右上角自定义连接器」点「信任」。

### ⚠️ 那个 `env` 不能省

WorkBuddy 启动 MCP server 时**不传 `USERPROFILE` 环境变量**，Python 的
`Path.home()` 会抛 `RuntimeError: Could not determine home directory`，
server 就找不到 `~/.unity-mcp` 下的状态文件，报「No Unity Editor instances found」。

`UNITY_MCP_STATUS_DIR` 让 server 跳过 `Path.home()` 直接定位状态目录。

### Unity 端的两个前提

1. **Transport 必须是 `stdio`**（`Window → MCP for Unity` 面板里改）
   - 选 HTTPLocal 时 Unity 不会开 TCP bridge，而 `8080` 端口被本机另一个软件
     （`luansha.exe`）占着，HTTP 模式也走不通
   - **改完要重启 Unity** —— stdio bridge 的启动逻辑写在静态构造函数里，
     只在域加载时执行一次，不重启不会生效
2. **Unity 要一直开着** —— bridge 跑在 Unity 进程里，监听 `127.0.0.1:6400`

## 使用前提

- **Unity 编辑器要保持打开** —— bridge 跑在 Unity 进程里
- Unity 里 `Window → MCP for Unity` 面板显示 **Connected**

## 排障

| 症状 | 处理 |
|---|---|
| Unity Bridge 连不上 | `Window → MCP for Unity` 看状态面板，必要时重启 Unity |
| Server 起不来 | 终端确认 `uv --version` 能跑（本机 uvx 在 `C:\Users\DELL\AppData\Local\hermes\bin\`） |
| 客户端连不上 | 确认 server 在跑；也可改用 HTTP 模式，配置 `"url": "http://localhost:8080/mcp"` |
