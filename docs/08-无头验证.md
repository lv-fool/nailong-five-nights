# 08 · 无头验证：不开编辑器也能跑测试和截图

> 写于 2026-10-19。适用于「没有图形界面 / AI 无人值守 / CI」这类场景，
> 也适用于你自己只想知道「改完这一版到底有没有崩」的时候。

## 一、本机的安装位置

| 东西 | 路径 |
|---|---|
| Unity 编辑器 | `F:\Unity\2022.3.62f3c1\Editor\Unity.exe`（2022.3.62f3c1，中国版） |
| Unity Hub | `C:\Program Files\Unity Hub\Unity Hub.exe`（3.3.7） |
| 许可证 | `C:\ProgramData\Unity\Unity_lic.ulf` |

中国版编辑器的包管理器域名是 `packages.unity.cn`。

## 二、跑 EditMode 测试（无人值守）

```powershell
# 1) 必须去掉代理环境变量：Unity 的 UPM 走 127.0.0.1:7890 会 ECONNRESET
Remove-Item Env:HTTP_PROXY,Env:HTTPS_PROXY,Env:http_proxy,Env:https_proxy,Env:ALL_PROXY -ErrorAction SilentlyContinue

# 2) 参数必须拼成一个带引号的字符串（路径里有空格！）
$argline = '-batchmode -nographics -projectPath "F:\nailong f" -runTests -testPlatform EditMode ' +
           '-testResults "F:\nailong f\.setup\editmode-result.xml" -logFile "F:\nailong f\.setup\unity-test.log"'
Start-Process -FilePath 'F:\Unity\2022.3.62f3c1\Editor\Unity.exe' -ArgumentList $argline
```

结果在 `.setup/editmode-result.xml`，根节点 `<test-run>` 上有
`total / passed / failed / skipped / result` 五个属性，直接读就行：

```powershell
[xml]$d = Get-Content 'F:\nailong f\.setup\editmode-result.xml' -Raw
$r = $d.'test-run'; "total=$($r.total) passed=$($r.passed) failed=$($r.failed)"
$d.SelectNodes("//test-case[@result='Failed']") | ForEach-Object { $_.name }
```

⚠️ 跑完 Unity 进程**不会自己退出**（没加 `-quit`，加了会让测试被掐断）。
它会一直攥着 `Temp/UnityLockfile`，导致下一次开图形界面报
「It looks like another Unity instance is running」。下次动手前先
`Get-Process Unity | Stop-Process -Force`。

## 三、Play 模式冒烟 + 截图

`-batchmode` 下面画面是空的，所以 Play 验证要**开图形界面跑**，
但过程仍然是无人值守的：命令行带 `-playSmoke` 时，
`Assets/Scripts/Diagnostics/PlaySmokeProbe.cs` 会在进 Play 后自动装载，
按时间轴做完一套动作后自己退出编辑器。

```powershell
$argline = '-projectPath "F:\nailong f" -playSmoke ' +
           '-executeMethod NailongFNAF.EditorTools.PlaySmoke.Run ' +
           '-logFile "F:\nailong f\.setup\play.log"'
Start-Process -FilePath 'F:\Unity\2022.3.62f3c1\Editor\Unity.exe' -ArgumentList $argline
```

它做的事（时间轴写死在 `PlaySmokeProbe.Update`）：

| 时间 | 动作 | 产出 |
|---|---|---|
| 1.5s | 截标题页 | `01_title.png` |
| 2.5s | 反射调 `PrototypeScene.OnEndlessClicked()` | — |
| 4.0s | 截图 + 模拟 3 轮门 / 监控 / 手电筒操作 | `02_endless.png` |
| 6.5s | 截图 + 打印时钟、电量、记点、HUD 文案 | `03_endless_after_actions.png` |
| 7.0s | 反射调 `ShowLoseEnd()`（会走永夜分支） | — |
| 8.5s | 截图 + 打印结算面板文案 | `05_endless_end.png` |
| 9.5s | 反射调 `OnStartClicked()` + `OnNightClicked(0)` | — |
| 11s | 截图 + 打印普通夜状态 | `04_normal_night.png` |
| 13s | 汇总错误数并 `EditorApplication.Exit` | 退出码 0 / 2 |

日志里搜 `SMOKE:` 看结论，截图落在 `.setup/play/`。
探针整段包在 `#if UNITY_EDITOR` 里，**不会进玩家包体**。

## 四、这套验证覆盖不到什么

- 声音、手感、鼠标灵敏度这类主观项，还得自己进 Play 摸一遍
- 敌人 AI 的真实压迫感（`EnemyDirector` 的随机性）不会在 12 秒里体现
- 打包：Windows 版的 IL2CPP 模块本机没装（只有 Mono），安卓包已经能正常出（见 `docs/10-安卓移植.md`）

## 五、排障：Unity 秒退、退出码 140063、一行日志都不写

**症状**：命令行启动 Unity 后约 3 秒退出，退出码 **`140063`**；`-logFile` 指定的日志和 stdout
都是 0 字节，`%LOCALAPPDATA%\Unity` 下也没有新日志、没有新崩溃目录，事件日志里没有新的
`APPCRASH` —— 是**干净退出**，不是崩溃、不是构建失败，Unity 根本没起来。

**2026-10-27 实测的记录**（同一台机器、同一个项目，正常桌面会话里能构建，受限权限下秒退）：

- `Unity.exe -version` 也是 3.2s 退出码 140063 → 与项目、场景、锁文件无关
- 把 `LOCALAPPDATA` 环境变量指到可写目录**没用**：Unity 用 KnownFolder API 取真实路径，不认这个 env
- 许可证本身没问题：`Editor\Data\Resources\Licensing\Client\Unity.Licensing.Client.exe --help`
  0.1s 退出码 0，打印 `Unity.Licensing.Client 1.16.2+bdef8f5`；`C:\ProgramData\Unity\Unity_lic.ulf` 也在

**原因**：以受限令牌 / 应用沙箱身份跑时，Unity 启动早期要写 `%LOCALAPPDATA%\Unity`（日志、许可缓存）
和 `ProgramData`，被拒就直接退。

**怎么办**：用**正常登录的桌面会话、普通用户权限**跑上面的命令；CI 里要给 Unity 完整的用户环境，
只给一个受限 token 就是这个症状。
