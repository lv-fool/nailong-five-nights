## 一、参考项目是什么

| 项 | 内容 |
|---|---|
| 原名 | **Saltline**（港区 3D 射击，中文版被改名为「几猫3A大作」） |
| 形态 | **一个 HTML 文件**，约 1.43 MB，离线可玩 |
| 渲染 | **Three.js r180 + WebGL2**，内嵌在文件里 |
| 素材 | **零外部素材**：贴图、模型、音频全部由代码在运行时生成 |
| 授权 | 仓库挂 MIT，但 README 明确说**原作（Saltline）授权未核实**；只能学方法，**不要拷代码/素材** |

它的核心思路：**文件里存的是「生成画面的配方」，不是画面本身。**
一块生锈铁板 = 一组噪声 + 锈斑 + 划痕规则；一把枪 = 若干几何体拼装；雨 = 实例化四边形 + 着色器。

## 二、它的画面是怎么搭起来的

### 2.1 渲染器与画质档

```js
new WebGLRenderer({ canvas, antialias:false, powerPreference:"high-performance",
                    alpha:false, depth:true, stencil:false })
outputColorSpace = SRGB
toneMapping = AgX（近似）
shadowMap.enabled = true; type = PCF; autoUpdate = false
autoClear = false
```

抗锯齿不用 MSAA 上下文，而是**自己建 MSAA RenderTarget**（0 / 2 / 4 采样随档位）。

画质预设（原值）：

| 档 | scale | msaa | shadow | tex | volSteps | ao | planar | bloom | motionBlur | rain |
|---|---|---|---|---|---|---|---|---|---|---|
| low | 0.70 | 0 | 2048 | 512 | 12 | 关 | 0 | 开 | 关 | 0.5 |
| medium | 0.85 | 2 | 2048 | 1024 | 16 | 开 | 0.5 | 开 | 关 | 0.8 |
| high | 1.00 | 4 | 4096 | 1024 | 24 | 开 | 0.5 | 开 | 开 | 1.0 |
| ultra | 1.00 | 4 | 4096 | 2048 | 40 | 开 | 1.0 | 开 | 开 | 1.0 |

还会按帧时间自动降档（最低档仍卡顿就继续降 scale）。

### 2.2 后处理链（自定义，不是 Three.js 自带 EffectComposer）

| Pass | 实现 | 参数（默认） |
|---|---|---|
| depth copy / depth half | 拷深度，半分辨率 | near 0.08 / far 900 |
| **SSAO** | 深度重建位置 + 法线，12 tap 螺旋采样 | 半径 0.9，强度 1.6 |
| **体积光** | 深度 + 阴影贴图做 ray-march | σ 0.0034，最远 170 m，12~40 步 |
| **Bloom** | 6 级降采样 + 升采样 | 强度 0.065，混合 0.62，dirt 0.1 |
| **Streak** | 横向光条（anamorphic） | 0.03，阈值 2.2 |
| **自动曝光** | 1×1 亮度纹理 + 时间适应 | key 0.12，曝光 0.6~2，tau 1.5 |
| **调色** | AgX 混合 + look | agxMix 0.25，power 1.18，sat 1.22 |
| **镜头** | 色差 / 暗角 / 颗粒 / 锐化 | CA 0.0013，vignette 0.3，grain 0.02，sharpen 0.3 |
| 运动模糊 | 可选 | 随画质开关 |
| 平面反射 | 湿地面 / 海面 | 精度 0 / 0.5 / 1 |

### 2.3 程序化材质（GPU 烘贴图）

一组 GLSL `surf()` 函数在 GPU 上烘焙成贴图图集，每个材质带：

- albedo / normal / roughness / metalness 多通道；
- `size`（世界尺寸）、`tile`（平铺次数）、`bump`（凹凸强度）。

材质名单（原代码里的键名）：
`asphalt`（沥青）、`concrete`、`brick`、`epoxy`、`paint`、`hull`（船体）、`galv`（镀锌）、`metal`、`brushed`（拉丝）、`rust`（锈）、`diamond`（花纹钢板）、`corrugated`（波纹板）、`chainlink`（铁丝网）、`hazard`（警示条纹）、`gunmetal`、`anodized`、`polymer`、`carbon`、`fabric`。

### 2.4 模型与场景

- 集装箱、仓库、吊车、船、枪、机械敌人：**全部用 `BufferGeometry` 拼**，再合并（merge）；
- 用**顶点色**区分同一网格里的不同材质区域（枪身、握把、弹匣）；
- 没有骨骼动画的敌人 = 分段零件 + 程序驱动旋转/位移；
- 文字/标线用 Canvas 画好再当纹理贴。

### 2.5 天空 / 海面 / 环境反射

- **天空**：专用 shader，输入 zenith / horizon / horizonAway / sun 颜色，`renderOrder = -1000`；
- **海面**：PBR 材质 + 顶点波动 + 自定义 shader 注入（`onBeforeCompile`），距离衰减波浪、反射太阳；
- **环境反射**：用 PMREMGenerator 从天空场景生成 env map，给金属/海面用。

### 2.6 天气与粒子

- 雨：**约 9000 根实例化雨柱 + 900 个地面溅射**，着色器里按相机位置循环包裹；
- 室内有 mask，室内不淋雨；
- 雾：`FogExp2` 风格，和天空/远处雾联动。

### 2.7 光照与阴影

- 方向光（太阳）+ 环境光；
- 阴影 PCF，2k~4k，**`autoUpdate=false`，按需刷新**（静态场景省开销）；
- 体积光从阴影贴图里采样，形成「雾中光柱」。

### 2.8 音频

WebAudio 程序合成：枪声、脚步、雨、海浪、雷、音乐声部，按战斗强度混音。同样零音频文件。

## 三、本项目现状（对照基线）

| 项 | 现状 |
|---|---|
| 引擎 | Unity **2022.3.62f3c1**，**Built-in** 管线 |
| 画面主体 | **一条 5120×1296 圆柱全景** `Assets/Resources/office_pano.png`，`OfficeRoom.cs` 程序化生成圆柱内壁 |
| 视角 | 相机绕中轴真转，`MaxYaw = 70°`，相机 `(0, 1.30, -1.20)`，全景覆盖 ±145°、斜率 ±0.72 |
| 世界物体 | 门板 / 敌人立绘 = `SpriteRenderer` 世界物体（门 1.2×2.05 m，敌人约 1.8 m） |
| UI | UGUI：墙上 DOOR/LIGHT 按钮、监控层、HUD、手电筒 |
| 监控层 | `MonitorArea` 固定 1920×1080，等比缩放；`MonitorCRT` / `MonitorStatic` / `MonitorSticker` / `MonitorCharacter` 四个 shader |
| 监控外模糊 | 另开 `_blurCam` 渲 1/6 分辨率 RT，只在监控升起时开 |
| 全局后处理 | **没有**：全项目 0 处 `OnRenderImage` / `CommandBuffer` / `Graphics.Blit` |
| 现有「后处理」 | 全部局限在监控画面：扫描线、颗粒、青绿色偏、暗角、行抖动（`MonitorCRT.shader`）；雪花（`MonitorStatic.shader`）；红屏蔓延（`RedSpread.shader`） |
| 画质 | 运行时强制 **Low**（`GameManager.ApplyPerformanceDefaults`：`SetQualityLevel(1)`、关 vsync、不限帧） |
| 光照 | 场景**没有实时光照**；办公室是 Unlit 全景，Standard 会渲成黑 |
| 音频 | 已接入 WAV/OGG 素材 + 部分程序合成（断电音乐盒） |

结论：**我们已经有「局部后处理」（监控 CRT）和全屏叠层（红屏、雪花），但没有「全屏氛围后处理」和「真实光照/反射」。**

## 四、逐项对照

| 他们的东西 | 我们能不能用 | Unity Built-in 实现路径 | 成本 | 建议 |
|---|---|---|---|---|
| Bloom（泛光） | ✅ | `OnRenderImage` + 亮度提取 + 多级模糊 + 合成 | 低 | **推荐** |
| 暗角 / 颗粒 / 色差 / 锐化 | ✅ | 一个全屏 shader 一次算完 | 低 | **推荐** |
| 自动曝光 | ✅ | 1×1 RT 降采样求亮度 + 时间适应 | 中 | 可选 |
| AgX 调色 | ⚠️ | Built-in 无内置 AgX，得自己写近似曲线 | 中 | 可选，先用简单 contrast/saturation |
| SSAO | ❌（当前场景） | 需要深度 + 法线；全景图是「假 3D」，没有几何深度 | 高 | 不做 |
| 体积光（ray-march） | ❌（当前场景） | 同上，缺深度；改成**光锥网格**才有意义 | 中 | 另做方案 B |

| 天空 / 海面 shader | ❌ | 没有室外场景 | — | 不做 |
| 雨 / 溅射 | ❌ | 室内办公室 | — | 不做 |
| 阴影贴图 | ⚠️ | 办公室无实时光；门/手机是 Unlit | — | 不做 |
| 画质档位 | ✅ | 已有 Low/Medium/… 档，可把新效果做成开关 | 低 | **推荐** |
| 程序合成音频 | ✅（部分） | 已有 Python 合成管线（断电音乐盒等） | 低 | 保持现状 |

## 五、三个可行方案

### 方案 A：全屏氛围后处理（推荐，风险最小）

**目标**：不碰现有画面结构，只在最终画面叠一层「恐怖片镜头」。

**实现**：

1. 新建 `Assets/Shaders/ScreenPost.shader`
   - Pass 1 `BloomPrefilter`：亮度阈值提取（`max(0, luma - threshold)`）；
   - Pass 2 `BloomBlurH` / Pass 3 `BloomBlurV`：降采样高斯模糊（2~3 级）；
   - Pass 4 `Composite`：Bloom 叠加 + 暗角 + 颗粒 + 色差 + 轻微对比度/饱和度。
2. 新建 `Assets/Scripts/UI/ScreenPostFx.cs`
   - `[RequireComponent(typeof(Camera))]`，挂在 `Camera.main` 上；
   - `OnRenderImage(src, dst)` 里按顺序 Blit；
   - 所有参数 `[Range]` 序列化，默认值参考：bloom 0.35、暗角 0.28、颗粒 0.015、色差 0.0008；
   - 提供 `enabled` / `Intensity` 总开关，接画质档位。
3. 与现有层共存：
   - **不要**把监控 CRT / 雪花 / 红屏并进来——它们已经各自工作；
   - 后处理作用在「最终合成图」上，监控画面也会被染上氛围（可接受；若要监控不受影响，可在监控升起时降低 Intensity）。

**注意**：
- `Camera.main` 的 `targetTexture` 不能被改（`WorldToScreenPoint` 会变成 RT 坐标，按钮/立绘全算错）——`OnRenderImage` 不碰它，安全；
- Built-in 的 `OnRenderImage` 在 UI Overlay 之前截屏，Screen Space Overlay 的 UGUI **不会被后处理**（这是好事：HUD 保持清晰；但监控如果是 Overlay，也不受影响）；
- 性能预算：1080p 下 4~5 个全屏 pass，中端卡约 0.5~1.5 ms；用 `QualitySettings` Low 时自动关 Bloom、只留暗角+颗粒。

**验证**：
- EditMode 测纯参数（强度夹取、档位开关）；
- Play 截图对比（开/关），存 `.workbuddy-ai/screenshots/`；
- Console 0 报错；`FrameTimingManager` 或简单 `Time.deltaTime` 看帧率。

### 方案 B：手电 / 门缝的体积光（进阶）

**目标**：强化「开灯才看得见」「手电照正门」这两条玩法。

**为什么不能用他们的 ray-march**：我们的办公室是全景贴图，没有真实深度/法线，屏幕空间体积光算不出来。

**替代做法（网格光锥）**：

1. 做一个锥体/棱柱网格（4~8 面即可），材质用加法混合 + 边缘柔和（`1 - dot` 或深度渐变）；
2. 手电：光锥挂在相机前方，跟着 `_pan` 转；只在手电亮着时显示；
3. 门灯：门洞处放一个朝外的光锥/光片，开灯亮、关灯灭；
4. 用 `ViewExternalPan` 同样的相机姿态驱动光锥朝向（避免和转头脱节）。

**成本**：中。要处理与全景的遮挡关系（门关着时不能漏光），建议只做「门洞内」和「手电近处」两段，别做全场体积雾。

**风险**：加法混合容易过曝；必须先调好亮度，再进 Play 看。

---

### 方案 C：真 3D 地板 + 湿地面反射（大工程，暂缓）

**目标**：把「全景里画出来的地面」换成真几何 + 实时平面反射。

**必须改的东西**：

1. `OfficeRoom.cs`：从「圆柱内壁 + 全景贴图」改成「真房间几何 + UV 映射」；
2. `tools/render_pano.py`：全景不再是唯一输出，要产出墙/地/顶的分块贴图；
3. 新增平面反射相机（镜像主相机），只渲地面层；
4. 所有按全景投影对齐的东西（门洞、按钮、立绘锚点）都要重算。

**成本**：很高。会推翻 `docs/04` 里「一条全景 + 相机真转」的核心约定，属于画面方案重做。

**建议**：除非明确要「重做办公室渲染」，否则不做。真想做反射，可以先在**桌面/手机屏幕**上做局部反射（小平面、低分辨率），风险小得多。

## 六、明确不建议照搬的

| 项 | 原因 |
|---|---|
| SSAO / 体积光 ray-march | 我们没有真实深度，全景是「贴图假 3D」 |
| 海面 / 天空 / 雨 / 溅射 | 室内场景，用不上 |
| 代码拼模型 | 现有 FBX + Sprite 管线够用，重做不划算 |
| WebAudio 程序合成整套音频 | 我们已有素材 + Python 合成管线，迁移成本高、收益低 |
| 自动降档 | 我们已固定 Low，且没有重负载；先不做 |

## 十、方案 A 实施记录（2026-11-14）

已按「轻微电影感」默认值落地，未做设置菜单（参数在 `ScreenPostFx` 的 Inspector 上）：

| 文件 | 作用 |
|---|---|
| `Assets/Shaders/ScreenPost.shader` | 三个 pass：亮度提取 / 可分离模糊 / 合成（Bloom+暗角+颗粒+色差+调色） |
| `Assets/Resources/ScreenPostMaterial.mat` | 走 `Resources.Load` 的材质（避免发行版剔除 shader） |
| `Assets/Scripts/UI/ScreenPostFx.cs` | 挂在主相机上的 `OnRenderImage`；Bloom 半分辨率；不碰 `targetTexture` |
| `Assets/Scripts/UI/ScreenPostPolicy.cs` | 纯逻辑：Bloom 画质门槛、监控减半、强度夹取 |
| `Assets/Tests/EditMode/ScreenPostPolicyTests.cs` | 7 条规则测试 |
| `Assets/Scripts/UI/OfficeRoom.cs` | `EnsureCamera()` 里补挂 `ScreenPostFx` |

默认值：总强度 0.85、Bloom 0.35（阈值 0.65）、暗角 0.28、颗粒 0.015、色差 0.0008。

已实现的约定：

- **Low 档不跑 Bloom**（`ScreenPostPolicy.BloomAllowed(1) == false`）——默认画质下只剩暗角/颗粒/色差，几乎零开销；
- **监控升起时总强度 ×0.5**（`EffectiveIntensity`）；
- 全屏后处理只作用于相机画面，**Screen Space Overlay 的 HUD / 监控层不受影响**；
- 强度为 0 时直接 `Blit` 透传，不申请任何 RenderTexture。

验证（2026-11-14）：

- EditMode **351 用例全通过**（含新增 7 条）；
- Play 实测：Low 档 `LastBloomRan=False`；High 档 `LastBloomRan=True`；监控升起时 `LastIntensity=0.43`（0.85×0.5）；
- 开/关对比截图量化：四角/中心亮度比从 **0.52 → 0.394**（暗角生效），画面差异均值 6.4（轻微）。
